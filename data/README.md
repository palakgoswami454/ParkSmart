`raw/dataset.csv` is included in this repository (redistribution is permitted under CC BY 4.0 with the attribution above).

**How this copy was obtained:** the UCI server was not reachable from the build environment, so the file was taken from a public GitHub mirror (`Alfarouk/ParkPulse/data/dataset.csv`). It was then checked against the UCI page: 35,717 rows, 4 columns with the documented names, 30 car parks, 2016-10-04 to 2016-12-19. `tests/test_pipeline.py::test_raw_matches_uci_description` repeats this check every time the tests run.

SHA-256 of the included file: `f1e28b9c697769a1a05cd20148241b60b1a73fee4907611163efc6fd9d12770a`

To replace it with a copy straight from UCI:

```bash
curl -L -o /tmp/parking.zip https://archive.ics.uci.edu/static/public/482/parking+birmingham.zip
unzip -o /tmp/parking.zip -d /tmp/parking && cp /tmp/parking/dataset.csv data/raw/dataset.csv
shasum -a 256 data/raw/dataset.csv     # compare with the hash above
```

## Raw schema

| Column | Type | Meaning (UCI) | Notes from our audit |
|---|---|---|---|
| `SystemCodeNumber` | string | Car park ID | 30 distinct values |
| `Capacity` | int | Car park capacity (spaces) | Constant for every car park; 220 – 4,675 |
| `Occupancy` | int | Number of occupied spaces | 12 negative values (sensor error); 373 above capacity (max 104%) |
| `LastUpdated` | datetime | Date and time of the reading | 07:46 – 16:30; median 33 min between readings |

There are **no missing cells** in the raw file, but there are **missing readings**: 216 exact duplicate rows, 4 calendar days with no data at all (20–21 Oct, 3–4 Dec), and some car parks with long sensor gaps. The full audit is in `processed/data_quality_report.json` (regenerated by `python -m src.data_preprocessing`).

## Processed files (generated)

* `processed/parking_30min.csv` – one row per car park × day × 30-minute slot (08:00 … 16:30). Columns: `SystemCodeNumber, slot_time, capacity, occupied, occupancy_rate, n_readings, date, slot, status`. Slots with no reading are left empty (never interpolated).
* `processed/data_quality_report.json` – raw audit, every cleaning decision and its row counts, status distribution.
